# Passcode-only portal (private pilot)
Student login defaults to a single secret-words input. Teacher login is a separate link, also with one secret-words input. No email or username is entered by either user.

The Supabase portal-login Edge Function resolves the one profile per role on the server, looks up its Auth account, and authenticates the supplied password through Supabase Auth. Only the publishable key is in frontend settings. The service-role key remains in the Edge Function environment. Auth accounts must be confirmed; password resets use their registered email. Disable public signups in the Supabase dashboard before deployment. Never commit credentials or real email addresses.

The database throttles login requests to eight per role in a five-minute window. This initial shared per-role limit can temporarily block legitimate sign-ins; review before expanding. Multiple students require a redesigned account lookup and rate limiting.

All 15 Safety lessons and their shared engine are imported and registered in the database. Teacher assignments control the student dashboard and the lesson session check. Static assets remain readable if publicly hosted. Progress is saved asynchronously and is not tamper-proof; avoid concurrent lesson tabs. Browser/authentication tests, content licensing, and deployment are pending. Publishing through GitHub Pages does not automatically make the site private.
